# GDI Content-Update Runbook

Operational steps for turning a COMMs request into a live change on
**www.valeindonesia.com**. Companion to the COMMs-facing guide
(`docs/COMMS-how-to-request-website-update.md`).

**Model:** COMMs authors → GDI reviews + deploys. Deploy to **dev first**, get a
**COMMs approver sign-off (Maman Ashari Hasan Tjokke)**, then deploy to **prod**. COMMs never touches Azure.

**Environments**
- Dev: storage account `stidstaticsite002`, endpoint `https://stidstaticsite002.z45.web.core.windows.net/`
- Prod: storage account `stidstaticsiteprod` behind Azure Front Door, public `https://www.valeindonesia.com/`

**Repo working tree:** `site/vale.com/` is the deployable output. News/docs pages are
generated by `build-news.py` / `build-doc-library.py` from `site-data/*.json`.

## 1. News request

COMMs authors news in a **visual form** (`make-news-editor.py` → an HTML page they fill
in a browser). Their submission is a **`news-record.json`** (bodies already HTML) plus the
image files. `intake-to-news.py` auto-detects `.json` and takes the same validated path as
the older Markdown template — you don't hand-edit the JSON either way.

> To send COMMs a form (blank or pre-filled from an article they want to base a new one on):
> ```bash
> python3 make-news-editor.py -o new-article.html                 # blank
> python3 make-news-editor.py -o new-article.html --from <slug>   # pre-filled from existing
> ```
> Hand them the resulting `new-article.html`; they double-click it, fill it, and Save
> downloads `news-record.json`.

1. **Place images on disk** (the converter prints the exact destinations):
   - Cover → `site/vale.com/documents/44618/<slug>/<file>`
   - Body images → `site/vale.com/documents/d/guest/<slug>-<n>-<ext>` (extensionless served name)
2. **Convert + validate + append the record** (never hand-edit the JSON):
   ```bash
   python3 intake-to-news.py <request-folder>/news-record.json --dry-run   # inspect first
   python3 intake-to-news.py <request-folder>/news-record.json             # writes + backs up
   ```
   (A legacy Markdown `request.md` still works — same command, `.md` path.)
   The tool validates date, category (against `FILTER_CHIP_ALLOWLIST`), slug uniqueness,
   folds in the baseline `["Indonesia","Indonesia news"]` tags, and maps the referenced
   image filenames to their on-disk destinations; it backs up `news-indonesia.json` to a
   timestamped `.bak-…` and self-checks the result re-parses. If it errors, fix the
   request and re-run — nothing was written.
3. **Build:**
   ```bash
   python3 build-news.py     # must exit 0
   ```
   Regenerates both listings, both `/w/<slug>.html` twins, and the homepage carousel.
4. Preview + deploy (Sections 5–6).

> Note: the converter appends the record; `build-news.py` sorts by date descending
> (newest first), so array position doesn't matter.

## 2. Document request

COMMs authors documents in a **visual form** (`make-doc-editor.py` → an HTML page they
fill in a browser). Their submission is a **`doc-record.json`** (section, title,
date_published, pdf_file, lang) plus the PDF. `intake-to-doc.py` validates it and derives
all the plumbing — folder id, `link`, `fsPath`, `sizeBytes`, `id`, `description` — so you
don't hand-edit `documents.json`.

> To send COMMs a form: `python3 make-doc-editor.py -o new-document.html` — hand them the
> file; they fill it and Save downloads `doc-record.json`.

1. **Place the PDF** on disk first (so `sizeBytes` reads the real size). The destination
   folder is the section's numeric id — the tool derives it, but for reference:
   Annual Reports = `1371772`, Sustainability = `1373270`, Financial = `1374000`,
   Presentation = `8997207`, Press Releases EN = `1438416` / BH = `1438419`.
   **Quarterly Reports** has no single folder (one per batch) — reuse the sibling batch's
   id and pass it with `--folder`. Spaces in the filename become `+` on disk:
   ```
   site/vale.com/documents/44618/<folder>/<PDF+with+plus+for+spaces>.pdf
   ```
2. **Convert + validate + append the record** (never hand-edit the JSON):
   ```bash
   python3 intake-to-doc.py <request-folder>/doc-record.json --dry-run   # inspect first
   python3 intake-to-doc.py <request-folder>/doc-record.json             # writes + backs up
   # Quarterly Reports only:
   python3 intake-to-doc.py <request-folder>/doc-record.json --folder <batch-id>
   ```
   The tool checks the section against `SECTION_ORDER`, requires EN/BH lang for Press
   Releases, encodes `link`/`fsPath` (spaces → `+`), stamps real `sizeBytes` from the
   staged PDF, assigns the next `id`, backs up `documents.json` to a timestamped `.bak-…`,
   and self-checks the result re-parses. If the PDF isn't on disk yet it warns and writes
   `sizeBytes: 0` — stage the PDF first, then run, for a correct card size.
3. **Build:**
   ```bash
   python3 build-doc-library.py   # must exit 0
   ```
4. Preview + deploy (Sections 5–6). PDFs keep their `.pdf` extension so MIME is automatic;
   verify `content-type: application/pdf` on the live URL anyway.

## 3. Existing-page edit

1. **Find BOTH bilingual twins** (they have DIFFERENT slugs):
   - EN: `site/vale.com/indonesia/<en-slug>.html`
   - ID: `site/vale.com/in/indonesia/<id-slug>.html`
   Use the request's page URL(s) and `grep -rl "old text" site/vale.com/` to locate.
2. Apply the old→new text edits and swap/add images per the request's language scope.
   Drop any new images on disk at the referenced paths.
3. If the change touches the language toggle target, re-verify the EN/ID pill points to
   the static twin, not a Liferay `update_language` URL (which 404s) — see `fix-lang-toggle.py`.
4. No builder needed (direct HTML edits). Preview + deploy the 1–2 changed files.

## 4. New page — from an EXISTING page (COMMs content, our layout)

When COMMs wants a new page shaped like an existing one (request template
`new-page-request.md`, `mode: from-existing`), use the page-content tools — COMMs
never edits HTML, and the chrome/layout is preserved exactly.

### Preferred: give COMMs a VISUAL editor (they see the real page)

COMMs edits on top of the actual styled page — no cryptic files, no HTML.

1. Copy the source page locally as the base for each new twin:
   ```bash
   cp site/vale.com/indonesia/<source-en>.html      site/vale.com/indonesia/<new-en>.html
   cp site/vale.com/in/indonesia/<source-id>.html   site/vale.com/in/indonesia/<new-id>.html
   ```
2. **Build a visual editor** for each twin and send the two `.html` files to COMMs:
   ```bash
   python3 make-page-editor.py site/vale.com/indonesia/<source-en>.html   -o content-en-editor.html --lang en
   python3 make-page-editor.py site/vale.com/in/indonesia/<source-id>.html -o content-id-editor.html --lang id
   ```
   Each editor is a self-contained file: COMMs **double-clicks** it (needs internet — it
   pulls the live site's CSS/images), sees the real page, clicks any highlighted heading/
   paragraph to type over it, clicks any highlighted image to replace it, then clicks
   **Save changes** → downloads `content-en.json` / `content-id.json`. They return those
   (plus any new image files) in the request folder.
3. **Inject** the saved JSON into the copied pages (inject auto-detects `.json`):
   ```bash
   python3 inject-page-content.py content-en.json site/vale.com/indonesia/<new-en>.html   -o site/vale.com/indonesia/<new-en>.html
   python3 inject-page-content.py content-id.json site/vale.com/in/indonesia/<new-id>.html -o site/vale.com/in/indonesia/<new-id>.html
   ```
   Inject verifies the fingerprint (editable count + type sequence) and ABORTS on any
   mismatch. It prints an image-placement worklist — copy each attached image to the
   printed `/documents/44618/<slug>/…` path.

### Fallback: the plain content file (`.md`)

If a visual editor isn't practical, `extract-page-content.py <page> -o content-en.md`
emits a plain text file COMMs edits (values between `«VAL»…«/VAL»`); inject the `.md`
the same way. Same fingerprint/abort safety. (This is the engineer-facing form — prefer
the visual editor for COMMs.)
5. Wire the plumbing (still manual): add the new pair to `fix-lang-toggle.py`'s
   `ID_EN_TWINS` map + run it so the EN/ID pill points twin→twin; add the page to the
   nav menu if needed; run `SITE_DIR=site/vale.com ./postprocess-bilingual.sh` scoped to
   the two new files to fold in the site-wide chrome fixes.
6. Preview + deploy (Sections 5–6).

Guarantees: extract→inject with no edits reproduces the source **byte-identical**
(verified across the site); an edited file changes ONLY the intended editable elements —
chrome/footer/nav are never touched. Round-trip integrity gate: `cmp` source vs a
no-edit inject must be identical.

Scope (v1): edit-in-place content swaps on a same-structure copy. Adding/removing whole
sections, or a truly bespoke layout, is a hand-built page — see the re-clone path below.

## 6. Deploy (dev → sign-off → prod)

Deploy **only the changed files** — never a full 1.3 GB re-upload.

### 6a. Dev
```bash
# per changed file (redirect </dev/null: az consumes a read-loop's stdin and skips files)
az storage blob upload \
  --account-name stidstaticsite002 --auth-mode login --overwrite \
  --content-cache "public, max-age=300" \
  --name "<blob-key>" --file "site/vale.com/<path>" </dev/null
# <blob-key> = the path WITHOUT the leading site/vale.com/
# set --content-type explicitly for any extensionless /documents/d/ file
```
Verify on dev by live HTTP (never `az download`, it can mangle content):
```bash
curl -sI "https://stidstaticsite002.z45.web.core.windows.net/indonesia/w/<slug>.html" | head
```

Share the dev URL(s) with the COMMs approver **Maman Ashari Hasan Tjokke**
(maman.hasan@vale.com / maman.hasan@valeindonesia.com). **Wait for approval** before prod.


Move the SharePoint request folder to `3-Done-Deployed/` and add a `deployed.txt`
(live URLs + timestamp).

## Gotchas (bite every time if forgotten)

- **Bilingual twins have different slugs** — always edit/verify BOTH `/indonesia/<en>`
  and `/in/indonesia/<id>`.
- **az stdin bug** — piping a filelist into `az` in a `while read` loop silently skips
  most files. Redirect each `az` call `</dev/null` (or use a Python subprocess with
  `stdin=DEVNULL`) and verify blob size == local after upload.
- **vale.com WAF** rate-limits burst curl hard and the block escalates. Fetch one page at
  a time with real gaps, or tether to a phone for a fresh IP.
- **Extensionless documents** (`/documents/d/…`) serve as `octet-stream` unless you set an
  explicit `--content-type`; PDFs under `/documents/44618/…/*.pdf` keep their extension
  and are fine.
- **Lang toggle** must point to the static twin, or it 404s (Liferay `update_language`
  URLs don't exist on the static host).
- **PIM is time-boxed** — prod deploys must finish inside the activation window; expect to
  re-activate + clear the token cache each prod session.
