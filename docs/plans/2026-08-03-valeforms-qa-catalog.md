## TASK 0 — Hero header image on Doc Library & News list pages  ← ACTIVE (this request)

**Problem:** On vale.com/indonesia, the Doc Library and News list pages have a
full-bleed hero image banner with "PT Vale Indonesia / [Page Title]" text
overlaid on it. This banner both (a) provides the visual page header and
(b) pushes content down so the title/content is not overlapped/hidden by the
fixed Vale top menu.

Our recreated pages have NO hero — the `<h1>` sits in a plain padded block
(`.doclib-header` / `.news-listing-header`, `padding: 3rem 0`) directly under
the menu, so the heading is cramped/overlapped by the menu bar.

Evidence (screenshots this session):
- Doc Library — theirs: full hero (worker in control room) w/ "PT Vale Indonesia /
  Documents and Reports" overlaid.  ours: "...ments and Reports" jammed under menu.
- News — theirs: full hero (field workers) w/ "PT Vale Indonesia / All News"
  overlaid.  ours: no hero, "All News" area overlapped, chips under menu.

**Goal:** Adopt the vale.com hero banner on our Doc Library and News list pages.
Full-bleed image, eyebrow "PT Vale Indonesia", large white title overlaid,
content clears the fixed menu.

**Where to change:**
- News list: `build-news.py` → `.news-listing-header` block (styles ~L276-277,
  markup ~L417-419). Replace plain header with hero markup + hero CSS.
- Doc Library: `build-doc-library.py` → `.doclib-header` block (styles ~L203-205,
  markup ~L371-374). Same hero treatment. Note doc lib header also carries the
  intro `<p>` — keep that (either inside hero or as the section subheading below).

**Open items to resolve before building:**
- Hero image source: which image(s) to use? vale.com uses specific photos. Need
  to either reuse the exact hero assets from the mirror/chrome, or pick suitable
  local images. CHECK: does the split-out `header` chrome already include a hero
  block on the real pages we can lift, or is main-content stripped of it?
